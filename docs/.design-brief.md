# Design Brief — Notes-to-Anki Vocabulary Shortcut

Status: INTERVIEW COMPLETE (pending final confirmations). Rough input: DesignDocument.txt (was empty).
Deliverable: business + technical requirements → DESIGN.md.

## Problem & goals
- **Problem:** The owner captures vocabulary in the iPhone Notes app in the moment but rarely
  turns it into Anki cards because building cards by hand is a chore. They want a one-tap path
  from a list of words in a note to finished, richly auto-populated Anki cards in a deck they
  choose — no computer involved.
- **Success metric:** Move from ~0% of captured words reaching Anki to ~100%.
- **Primary user:** the owner only. Single user. Not multi-user, not published.
- **Non-goals (confirmed):**
  - **No translation anywhere on the card** — definitions and examples are monolingual, in the
    target language. Enforced by the generation prompt AND a post-generation validator.
  - No general famous-quotations feature — the "quote" idea is satisfied by a song-lyric line.
  - No AnkiMobile (paid) and no AnkiDroid (Android).
  - No images / audio / cloze / rich card types in v1 [ASSUMPTION — veto later].
  - Delete-from-deck is a real requirement but OUT of v1 (see Scope / Milestones).
- **Constraints:** iPhone + Apple Shortcuts as the only client. Must run at **$0** — free
  hosting and the **Google Gemini free-tier API** via its OpenAI-compatible endpoint (no paid API key). No hard deadline.

## Users & scenarios
- **User types:** (1) Owner, on iPhone, running Shortcuts. (2) The always-on backend host
  (operated by the owner).
- **Scenario A — Add batch (the common case):**
  1. Owner has 1–10 terms, one per line, in a note.
  2. Runs the "Add to Anki" Shortcut (share sheet from the note, or run + pick the note).
  3. Shortcut prompts for **target language** (default pre-filled) and **target deck** (list
     fetched live from AnkiConnect → Choose from List).
  4. Shortcut POSTs `{terms[], language, deckName, secret}` to the backend.
  5. Backend, per new term: dedup-check against Anki → call the LLM for card content →
     validate → (optionally) fetch a lyric → assemble a note → add via AnkiConnect.
  6. Backend returns `{added[], skipped[], failed[]}`.
  7. Shortcut shows a summary: `added: N / skipped (dup): M / failed: K (term, term)`.
- **Scenario B — Deck pick:** Shortcut → AnkiConnect `deckNames` → Choose from List. Used
  inside Scenario A; this is the mechanism that lets the owner "specify the deck".
- **Scenario C — Delete a word (LATER, not v1):** separate Shortcut; owner supplies term
  (+ deck); backend `findNotes` then `deleteNotes`; confirmation UX TBD.

## Scope
- **IN (v1):** read terms from a note; pick language; pick deck; list decks; per new term
  generate a full card via a free LLM {monolingual definition, example sentence, register,
  and — where relevant — connotations and implications}; add a Musixmatch lyric + song title
  where one exists; dedup; add notes to the chosen deck; return a per-run summary; tag cards
  with missing/failed content.
- **LATER:** delete flow; supplementary real-corpus example sentences from Reverso; automatic
  retry queue for offline runs; richer card types; a lookup/response cache.
- **OUT (permanently):** translations on cards; multi-user; a hosted service for anyone else.

## Functional requirements (v1)
- **FR1 Capture** — Shortcut reads the note body, splits on newlines into entries, trims
  whitespace, drops blank lines. An entry may be a single word OR a multi-word
  expression/idiom, and is assumed to be the raw term only (no appended personal note)
  [ASSUMPTION]. Case/diacritics preserved as typed.
- **FR2 Language select** — Shortcut asks for the target language each run, pre-filled with a
  configurable default. Language is an explicit input, NOT derived from the deck (decks are
  organised by topic). Target languages in scope: **French, Spanish, Norwegian**; the pipeline
  is language-agnostic (language is a passthrough parameter to the prompt and to Musixmatch).
  Known coverage gap: Norwegian song coverage in Musixmatch is thin.
- **FR3 Deck select** — Shortcut fetches the current deck list from AnkiConnect and lets the
  owner choose one. If the deck list can't be fetched, the run aborts with an error (FR8).
- **FR4 Generate card content** per new entry, via the **Google Gemini free-tier API**
  (OpenAI-compatible endpoint `https://generativelanguage.googleapis.com/v1beta/openai/`;
  model by config, default e.g. `gemini-2.5-flash`; provider still swappable via
  `LLM_BASE_URL`/`LLM_MODEL`), one structured request per term (JSON mode / response schema)
  returning:
  - `definition` — a monolingual definition **in the target language**, learner-dictionary
    style. Required.
  - `example` — one natural example sentence in the target language. Required.
  - `register` — a short note on register/formality. Required.
  - `connotations` — only when the word carries notable connotation; else empty.
  - `implications` — only when the word carries notable pragmatic implication; else empty.
  - The prompt forbids translation and any non-target-language text in `definition` /
    `example`.
- **FR5 Validate LLM output** — before a card is created the backend checks: valid JSON with
  the expected keys; `definition` and `example` non-empty and (heuristically) in the target
  language, not English/translation; length bounds. On validation failure → one retry, then
  the entry is reported `failed` (no card) and re-tried next run.
- **FR6 Lyric enrichment** — backend queries **Musixmatch (Python package)** for a lyric line
  + song title containing the term. On no match → `Lyric`/`SongTitle` blank, **no tag**, card
  still created.
- **FR7 Add to Anki** — backend creates one note of the new note type in the chosen deck via
  AnkiConnect (`addNotes`, batched).
- **FR8 Dedup** — before generating/adding, the backend checks Anki for an existing note whose
  `Word` field equals the entry **in the same target deck** (`findNotes` / `canAddNotes`). If
  found, the entry is skipped and reported `skipped (dup)`. The note in Notes is never
  modified; re-running is always safe. Consequence: a hand-edited card is preserved (skipped on
  re-run); a deleted card is recreated on the next run [ASSUMPTION — acceptable].
- **FR9 Run summary** — backend returns, and the Shortcut displays,
  `added / skipped (dup) / failed (with terms)`.
- **FR10 Error surfacing** — if the backend or Anki is unreachable, or the deck list fails,
  the Shortcut shows a plain error and the owner retries later. No automatic retry/queue in v1.
- **FR11 Partial-batch tolerance** — one entry's failure (LLM error, rate limit, validation,
  addNote error) never aborts the batch; other entries still process. Failed entries are
  re-attempted on the next run (FR8 prevents duplicates).
- **FR12 Missing-content tagging** — a card created despite a *non-fatal* gap carries a tag:
  `needs-lyric` is NOT used (silent). If `connotations`/`implications` are empty that is
  normal, no tag. (Definition/example can't be empty — those are fatal → `failed`, per FR5.)

## Interactions & data flow (edge list)
| # | From | To | Trigger | Payload | Response | Mode | Mechanism | Idempotent | On failure |
|---|---|---|---|---|---|---|---|---|---|
| E1 | Shortcut | AnkiConnect | Owner starts a run | `{action:"deckNames",version:6}` | `{result:[deck names]}` | sync | HTTP POST :8765 over tailnet | yes | Abort run; "can't reach Anki" |
| E2 | Shortcut | Backend | Owner confirms language + deck | `{terms[], language, deckName, secret}` | `{added[], skipped[], failed[]}` | sync (long) | HTTPS over `tailscale serve`, shared-secret header | yes (FR8 dedup) | Show error; nothing added; owner retries |
| E3 | Backend | AnkiConnect | Per term, before generating | `findNotes`/`canAddNotes` for `Word:term` in `deckName` | exists? true/false | sync | HTTP POST :8765 | yes | Count entry `failed`, continue batch |
| E4 | Backend | LLM provider | Term is new | prompt(term, language) requesting strict JSON | `{definition, example, register, connotations, implications}` | sync, timeout ~15s | HTTPS, OpenAI-compatible `/chat/completions` | yes | 1 retry; then entry `failed` |
| E5 | Backend | LLM output validator | LLM responded | raw model JSON + target language | accept / reject(reason) | sync | in-process | yes | reject → 1 regen (E4) → then `failed` |
| E6 | Backend | Musixmatch | Card content valid | term (+ language) | lyric line + song title, or none | sync | Python pkg → Musixmatch web API | yes | blank Lyric/SongTitle, no tag, continue |
| E7 | Backend | AnkiConnect | Note assembled (batched) | `addNotes` with note-type fields + deck + tags | note IDs | sync | HTTP POST :8765 | yes (guarded by E3) | entry `failed`; batch continues |
| E8 | Backend | Shortcut | All terms processed | `{added[], skipped[], failed[]}` | — | sync (response to E2) | HTTP response | yes | covered by E2 failure |
| E9 | Shortcut (Delete) | Backend → AnkiConnect | LATER | term (+ deck) | matches + delete confirm | sync | as E2/E3 | n/a | LATER |
| E10 | Backend | Reverso (LATER) | Card content valid | term + language | example sentence(s), translations stripped | sync | HTTPS (unofficial) | yes | blank supplementary example, tag `needs-example` |

- **Key flow 1 — Add batch:** E1 → owner picks deck → E2 → per term: E3 → E4 → E5 (→ maybe
  back to E4) → E6 → E7 → then E8 → summary shown.
- **Key flow 2 — Deck pick:** E1 → Choose from List (subset of flow 1).
- **Key flow 3 — Delete (LATER):** E9.
- **Cycles:** only E4↔E5 (regen on validation failure) — bounded to **1 retry**, then `failed`.
- **Shared state:** the Anki collection is written only by AnkiConnect (single writer); the
  backend serialises `addNotes` per run.
- **Startup order:** Anki + AnkiConnect must be up before a run; if not, E1 fails fast and the
  run aborts. LLM provider and Musixmatch are per-term and degrade gracefully.
- **Backpressure:** batch capped at ~10 entries; backend processes terms sequentially, so LLM
  free-tier rate limits are hit one call at a time and handled per entry (E4 retry/`failed`).

## Data & state
- **New Anki note type** (name TBD — proposed `Vocab` [ASSUMPTION]). One card template, no
  reverse card. Fields: `Word`, `Definition`, `Example`, `Register`, `Connotations`,
  `Implications`, `Lyric`, `SongTitle`, `Language`, `AddedDate` (`Language`/`AddedDate` for
  later filtering — [ASSUMPTION], veto ok). Front: `{{Word}}`. Back: everything else, with
  empty fields rendered as nothing (conditional `{{#Field}}` sections).
- **Tags:** `needs-example` (only if Reverso path is added later). No other tags in v1.
- **Prompt template** is a versioned config asset on the host (cf. otjServices
  `src/main/resources/llm_prompt.txt`).
- **Term parsing:** one entry per line; trim; drop blanks; entry may be a phrase.
- **Backend state:** stateless per request; no database; no lookup/response cache in v1
  [ASSUMPTION].
- **Source of truth:** the Anki collection on the always-on host, synced to AnkiWeb → the
  owner's devices.

## Cross-cutting concerns
- **Access control (per otjServices pattern):** the backend and AnkiConnect are **bound to
  `127.0.0.1` and exposed only via the host's `tailscale serve --https`** — there is no
  public port and no firewall rule for them at all. A low-privilege rotatable shared secret in
  a request header is kept as defence in depth (its only power is "submit terms"). Sensitive
  keys (LLM key, Musixmatch token, AnkiConnect apiKey) live only on the host env file; the
  Shortcut holds only the backend URL + the shared secret (plaintext, iCloud-synced —
  accepted, mitigated by tailnet + low privilege).
- **Config (host env file):** `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, Musixmatch token,
  AnkiConnect apiKey, shared secret, note-type name. **In the Shortcut:** backend URL, shared
  secret, default language. Tag strings and timeouts are constants.
- **LLM guardrails:** strict-JSON request; schema + language + length validation (FR5); one
  regen on failure; never create a card from unvalidated output; log the rejected payload at
  debug only.
- **Performance:** batch ≤ ~10 entries; no user latency target; per-LLM-call timeout ~15s
  [ASSUMPTION]; overall run cap so the Shortcut never hangs; a summary is always returned.
- **Cost:** target $0 — free LLM tier + free/owned hosting. Risk = free-tier quotas, handled
  as per-entry `failed` + safe re-run.
- **Observability:** a per-run log on the host (terms in, per-term outcome incl. validation
  rejections, errors). The owner learns of problems from the Shortcut summary; deeper
  diagnosis via the host log. No alerting in v1 [ASSUMPTION].
- **Security:** untrusted input is the term list (low risk; sanitise before URL/shell/prompt
  use — including basic prompt-injection hygiene since terms go into an LLM prompt). Musixmatch
  package + (later) Reverso are the supply-chain risks. Secrets in the host env file, never in
  version control.

## Failure modes
| Component / edge | Failure | Detection | Response | Owner sees | Blast radius |
|---|---|---|---|---|---|
| Backend host / tailnet | down / unreachable | Shortcut request error (E2) | none (no queue v1) | "Couldn't reach backend, try later" | whole feature down until back |
| Anki / AnkiConnect | not running / crashed | E1 or E3/E7 error | run aborts (E1) or entry `failed` (E3/E7) | error, or `failed` in summary | no cards added that run |
| LLM provider | down / 5xx / timeout | HTTP error / timeout on E4 | 1 retry → entry `failed` | term under `failed` | that entry; if persistent, whole batch fails one-by-one |
| LLM free-tier limit | 429 / quota exhausted | 429 on E4 | brief backoff + 1 retry → entry `failed`; re-run later | terms under `failed` | remaining entries in the batch |
| LLM output bad | invalid JSON / wrong language / translation present / empty required field | validator (E5) | 1 regen → then entry `failed` | term under `failed` | that entry |
| Musixmatch pkg | no match / package broken | empty / exception | blank lyric, no tag, card still made | lyric simply absent | one field |
| addNotes (E7) | AnkiConnect rejects (dup slipped through, bad field) | error in response | entry `failed`, batch continues | term under `failed` | one entry |
| Partial batch | some added, some failed | per-entry outcomes | summary lists them; next run retries failed; FR8 stops doubles | `added / skipped / failed` counts | none — self-heals on re-run |

- **Single points of failure:** the always-on host (backend + Anki). Accepted for v1.
- **Recovery:** every recovery path is "re-run the Shortcut"; dedup makes that safe.

## Alternatives considered
| Option | Why not (v1) |
|---|---|
| Paid Anthropic / OpenAI API for card content | Costs money and needs a billed key; free OpenAI-compatible providers cover this use. Would be the upgrade if free-tier quality/limits prove inadequate. |
| Reduced free-API card (Wiktionary + Reverso + Musixmatch, no LLM) | Loses register / connotations / implications — the nuance the owner considers the point of the card. Kept as the fallback if the free LLM path fails. |
| AnkiMobile + its URL scheme / share sheet | Paid app — the cost the owner is avoiding. |
| Shortcut → AnkiConnect directly, no backend | Musixmatch (and LLM calls, validation, parsing) need Python; Shortcuts can't run it. |
| Home-desktop-only AnkiConnect (LAN) | Not always available; every capture made away from home fails. |
| genanki → .apkg | Needs a manual import step on the phone — breaks "one tap". |
| Reverso as the definition source | Bilingual/translation-based — violates the no-translation rule. |

### Assumptions
- **A1** One entry per line; an entry may be a multi-word expression; entry is the raw term
  only; case/diacritics kept as typed.
- **A2** Plain single-template card, no media/cloze in v1.
- **A3** Single user; one always-on backend instance.
- **A4** Backend is stateless per request; no database or cache in v1.
- **A5** Per-LLM-call timeout ~15s; overall run cap; summary always returned.
- **A6** No alerting in v1; a per-run host log is enough.
- **A7** New note type `Vocab`, fields `Word, Definition, Example, Register, Connotations,
  Implications, Lyric, SongTitle, Language, AddedDate`.
- **A8** `definition` and `example` are mandatory → their absence is a `failed` entry, not a
  tagged card. `connotations`/`implications` empty is normal, untagged. Lyric missing is
  silent.
- **A9** Dedup key = `Word` field exact match within the target deck; edited cards survive a
  re-run, deleted cards get recreated.
- **A10** `connotations` / `implications` relevance is the LLM's call, gated only by the
  prompt, not a rule engine.
